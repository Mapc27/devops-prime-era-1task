# M1 — детекция нарушений в тексте объявления

Каскад двух моделей: решение принимает `s-nlp/russian_toxicity_classifier`
(178M, лучшее покрытие видов нарушений), вид нарушения для объяснения продавцу
добавляет `cointegrated/rubert-tiny-toxicity` (11.8M, multilabel) — и только
для уже помеченных текстов.

## Запуск

```bash
.venv/bin/python m1_text/predict.py --text "Продам гараж, документы готовы"
.venv/bin/uvicorn m1_text.api:app --port 8000      # документация: /docs
.venv/bin/python m1_text/bench_api.py --n 300         # замер сервиса
```

Вывод содержит `decided_by` (какая модель приняла решение) и `thresholds`
(по каким порогам и на каких данных они подобраны).

**Вторая ступень каскада запускается только для помеченных текстов.** Если
решение `allow`, модель-объяснитель не загружается вообще — на чистом потоке
её в памяти нет. Чтобы увидеть обе ступени на любом тексте:

```bash
.venv/bin/python m1_text/predict.py --text "..." --explain     # всегда обе
.venv/bin/python m1_text/predict.py --text "..." --no-cascade  # только решающая
```

## Калибровка порогов

Пороги лежат в `thresholds.json` и **привязаны к модели и к данным**, на которых
подобраны. Файл хранит эту привязку в поле `fitted_on`; проверяйте его, если
результаты выглядят странно. Пересчитать:

```bash
.venv/bin/python m1_text/download_data.py --limit 6000     # публичный корпус
.venv/bin/python m1_text/evaluate.py --dataset m1_text/data/samples.csv \
    --prior 0.05 --target-recall 0.85 --cv 5 --tag domain_final --save-thresholds
```

`--prior 0.05` — ожидаемая доля нарушений в потоке, `--target-recall 0.85` —
какую долю нарушений обязаны хотя бы показать модератору. Второй параметр
управляет разменом «нагрузка на модераторов против утечки»:

```bash
.venv/bin/python m1_text/evaluate.py --dataset m1_text/data/samples.csv \
    --prior 0.05 --sweep-recall 0.95 0.85 0.75 0.65
```

## Результаты

| Модель | Публичный корпус | Объявления | p50 на текст |
|---|---|---|---|
| rubert-tiny, 11.8M | ROC-AUC 0.9977 | 0.8148 | 1.09 мс |
| russian_toxicity, 178M | ROC-AUC 0.9985 | **0.9433** | 12.79 мс |
| каскад | — | — | 13.3 мс (p95 19.3) |

Рабочая точка при порогах 0.005 и 0.1372:

| | allow | review | reject |
|---|---|---|---|
| чистые объявления (100) | 91 | 9 | **0** |
| нарушения (100) | 15 | 30 | 55 |

На выборке подбора ни одно честное объявление не отклонено; 15% нарушений
проходят в публикацию — это плата за выбранную рабочую точку.

**Но пороги подобраны и проверены на одних и тех же 200 текстах.** При 5-кратной
кросс-валидации (`--cv 5`) на отложенных данных отклоняется 2 честных объявления
из 100, и в пересчёте на поток с 5% нарушений precision(reject) падает до
0.61 — требование ТЗ 0.95 не подтверждается. Перед включением
автоматического отказа пороги нужно перекалибровать на реальных объявлениях.

HTTP-сервис (`bench_api.py`): p50 15.6 мс, p95 17.8 мс на запрос вместе
с разбором HTTP. Обе модели каскада загружаются и прогреваются при старте.

## Что важно знать

- **Лёгкая модель детектирует лексику, а не намерение.** На фразе «найду
  и проблемы будут» её голова `threat` выдаёт 0.000. Поэтому решение принимает
  тяжёлая модель.
- **Часть угроз система всё равно пропускает.** Из 15 угроз в тестовом наборе
  5 отклоняются, 8 уходят модератору, 2 проходят в публикацию. Пример
  пропускаемой: «Если не купишь — пожалеешь об этом» (оценка 0.0033). Угрозы
  без бранной лексики — слабое место готовых моделей токсичности.
- **Система не выдумывает причину отказа**: вид нарушения называется только при
  уверенности выше 0.5, иначе объявление идёт на ручную проверку.
- **Пороги не переносятся между доменами**, хранятся в `thresholds.json`
  с пометкой, на каких данных подобраны.
